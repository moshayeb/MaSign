# API reference

Interactive docs at `http://localhost:8000/docs`.

Every `/api/contracts/*`, `/api/questions/*` and `/api/standards/*` route (and `/api/query`) requires
a signed-in session and is scoped to the caller's own workspace (MAS-143): a
contract, link or question belonging to another workspace is 404, identical to
one that does not exist, never a 403 that would confirm it exists. `/api/auth/*`
is the exception and needs no session (register/login themselves cannot).

| Method | Path | Purpose |
|--------|------|---------|
| `POST` | `/api/auth/register` | `{"email", "password"}` → create an account and its personal workspace (MAS-143), sign in, and set the session cookie. 409 (a generic message, never confirming the email is taken) if it already exists; 422 for an invalid email or a password under 8 characters. |
| `POST` | `/api/auth/login` | `{"email", "password"}` → sign in and set the session cookie. 401 with the same generic message for either a wrong password or an unknown email. |
| `POST` | `/api/auth/logout` | Delete the session server-side (a real revocation, not just clearing the cookie) and clear it. 204. |
| `GET`  | `/api/auth/me` | The signed-in user's `id`/`email`. 401 if there is no valid session. |
| `POST` | `/api/contracts/upload` | Upload a TXT/PDF/DOCX contract; parses, chunks and stores it, then starts the risk review in the background. Returns the `contract_id` and `risk_status: pending`. Indexes into the required `portable` embedding profile and, best-effort, into the optional `quality` profile if configured (MAS-62 compare mode) — a `quality` indexing failure never fails the upload; `indexed_profiles` on the response says which actually succeeded. |
| `GET`  | `/api/contracts` | List stored contracts, newest first, with review status, worst severity, completeness, checked/total passage counts, `ingestion_notes`, the MAS-107 `document_kind` evidence, `indexed_profiles` (MAS-62), and the MAS-101 summary strip: `recurring_fee`, `initial_term` (text, from stored key terms), `high_findings` (High-severity risk count), `deviations` (MAS-96), `key_terms_status` (`complete` \| `partial` \| `none`) — all read from stored rows, no model call. |
| `GET`  | `/api/contracts/{contract_id}` | One contract's metadata (404 if unknown). |
| `DELETE` | `/api/contracts/{contract_id}` | Permanently remove a contract (MAS-126): its chunks, risk review, key terms, stored questions and links cascade in Postgres; its vectors are removed from Qdrant too (best-effort — a Qdrant failure is logged, not fatal, since Postgres already no longer has the contract). 404 if unknown. Irreversible; the UI confirms first. |
| `GET`  | `/api/contracts/{contract_id}/links` | Contract bundles (MAS-137): every other contract explicitly linked as the resolution of one of this contract's external references (MAS-84), with the `reference_name` each link resolves. |
| `POST` | `/api/contracts/{contract_id}/links` | `{"linked_contract_id", "reference_name"}` → link an already-uploaded contract as the resolution of a named reference. `reference_name` must be one of this contract's current, unresolved external references (never inferred from filename or content) — 400 otherwise; 404 if either contract is unknown. |
| `DELETE` | `/api/contracts/{contract_id}/links/{link_id}` | Remove a link. Invalidates this contract's existing risk review (`status: failed`) so it is never left silently claiming coverage of a document it no longer includes. |
| `GET`  | `/api/contracts/{contract_id}/risks` | The whole-contract risk review: `status` (pending / running / done / failed), the model, passages checked, `complete`, the verified `findings` (category, severity, reason, quoted clause, passage), the seven `categories` with their worst severity, the `key_terms`, the `clauses` checklist (MAS-188: `present` with a quoted passage / `absent` / `cannot_tell`, plus `clauses_complete`), the `policy` content-rule verdicts (MAS-192: `compliant` / `violated` / `cannot_tell` / `not_applicable` for a present clause with a configured rule, plus `policy_complete`), and `coverage` (MAS-84: `unreadable_passages`, `withheld_passages`, `ingestion_notes`, `external_references`, and the `document_kind` of MAS-107). Runs automatically after upload. |
| `GET`  | `/api/contracts/{contract_id}/search` | `?q=<question>&limit=5` → the passages the question would be answered from, best first, with scores. Retrieval only, no model call (MAS-91). Scoped to the contract's bundle (itself plus any linked documents), same as `/api/query` (MAS-151). |
| `GET`  | `/api/contracts/{contract_id}/passages` | This document's stored passages in order (`chunk_id`, `chunk_index`, `text`). A bundle result can cite another linked document; its `contract_id` identifies whose passages to open (MAS-83). |
| `GET`  | `/api/contracts/{contract_id}/key-terms` | Ten key terms (effective date, recurring fee, one-off fees, payment deadline, late-payment interest, termination cost, initial term, renewal, notice period, price changes), each `found` with its value, verbatim quote, passage and typed fields, `conflicting` when passages disagree, `not_stated` only when every passage was read, else `unchecked`. Also embedded in `/risks` as `key_terms`. |
| `GET`  | `/api/contracts/{contract_id}/export.pdf`, `export.docx`, `export.md`, `export.csv`, `export.xlsx` | The review as a file (MAS-154, MAS-191): searchable PDF, Word document, or Markdown with coverage, key terms and findings; or CSV/XLSX with one row per finding, key term and deadline. All five render the same `/risks` + `/key-terms` data — one row-building function shared by CSV and XLSX, one line-based renderer shared by PDF and DOCX — so no format can say something another doesn't; 404 before a review. |
| `POST` | `/api/contracts/{contract_id}/review` | Re-run the risk review and key-terms extraction. The start is atomic: one request gets 202; concurrent attempts get 409 while it runs. |
| `POST` | `/api/contracts/{contract_id}/rfi-suggestions` | `{"chunk_id", "category"}` → draft one clarifying question (an RFI) for a currently-flagged finding, identified by its stable `(chunk_id, category)` pair (MAS-189) — the first MaSign output the model *generates* rather than extracts. One model call, never batched or automatic. Stores a snapshot of the finding's `category`/`reason`/`quote` at generation time, not a live reference (`risk_findings` rows churn on every re-review). 404 if the contract is unknown or that finding is not currently flagged; 503 if the model's reply could not be read as a usable question (nothing is stored). Never a replacement clause ("redline") — out of scope for this ticket. |
| `GET`  | `/api/contracts/{contract_id}/rfi-suggestions` | Every drafted RFI stored for this contract, newest first (MAS-189). |
| `POST` | `/api/query` | `{"question", "contract_id"?, "limit"?, "profile"?}` → `answer` with `[n]` citations resolved in `citations`; `grounded` requires valid citations, a complete reply, and every detected money amount, percentage, date and duration to occur in a cited passage. It is false for "Not found in contract.". `retrieved_context` lists every passage considered, best first; `risks` holds the rubric findings ([risk rubric](risk-rubric.md)) with severity, reason and the quoted clause, `risks_checked` says whether the analysis ran; `blocked_passages` lists passages the prompt-injection guardrail withheld. Omit `contract_id` to search every contract. `profile` (MAS-62, default `portable`) picks the embedding index searched; the response echoes it back. `profile: "quality"` is 409 if that profile is not configured on this server, or if this specific contract was never indexed into it (`contract_id` given, no points found) — never a silent fallback answered under the "quality" label. Needs `ANTHROPIC_API_KEY` (or `CHAT_PROVIDER=openai` + `OPENAI_API_KEY`); otherwise 503 with the reason. A successful answer (never a refused/`withheld` one) is stored (MAS-102) so it can be read back without asking the model again. |
| `GET`  | `/api/contracts/{contract_id}/questions` | Previously answered questions for this contract, newest first (MAS-102): each with its `question`, `answer`, `answer_status`, `grounded`, and the full stored `response` (the original `QueryResponse`, so citations and flags render without a new model call). Includes a no-scope ("all contracts") question if its answer actually cited this contract. |
| `DELETE` | `/api/questions/{question_id}` | Forget a stored question (MAS-102). 404 if unknown. |
| `POST` | `/api/contracts/{contract_id}/invoices` | Upload a digital PDF invoice and check it against this contract's verified key terms (MAS-92) — a separate path from `/api/contracts/upload`: never indexed for search, never risk-reviewed. Extracts the invoice's own header fields with one model call (verbatim-quote verified, same discipline as key terms), then compares fee amount, payment deadline and late-payment rate against the contract's bundle-aware key terms (MAS-137/138). Returns a persisted result: each compared item is `match`, `possible_mismatch` (both sides' quotes shown) or `cannot_verify` (ambiguous, unsupported, or not safely comparable — different currency, an unstated billing period, incompatible rate shapes) — never a silent "clean" result. 404 if the contract is unknown; 415 for a non-PDF upload; 422 for a PDF with no text layer (OCR is out of scope). |
| `GET`  | `/api/contracts/{contract_id}/invoice-checks` | Past invoice checks for this contract, newest first (MAS-92). |
| `GET`  | `/api/invoices/{invoice_id}/pages` | An invoice's stored page text, in order — the citation behind each invoice-side quote (MAS-92). |
| `GET`  | `/api/standards` | The signed-in workspace's four editable Customer-side standards (MAS-120/181), read from its *default* standard profile (MAS-185) — unchanged from before named profiles existed. Current `params`, human-readable `text`, and `is_default` (no override saved for this term in this profile). 401 without a session. |
| `PUT`  | `/api/standards/{term_id}` | `{"params": {...}}` → validate and save one standard in the workspace's default profile (422 with a plain-language reason if invalid); it changes that profile's key-terms/deviation reads with no model call or re-review. 404 for an unknown `term_id`. |
| `DELETE` | `/api/standards/{term_id}` | Restore MaSign's built-in default for one standard in the workspace's default profile (removes its saved row). 404 for an unknown `term_id`. |
| `GET`  | `/api/standard-profiles` | Every named standard profile in the signed-in workspace (MAS-185), each `{id, name, is_default}`. A lazily-created "Default" profile always exists — current users see no behaviour change. |
| `POST` | `/api/standard-profiles` | `{"name": "..."}` → create a new, empty (all-built-in-default) profile. 201; 409 if the name is already used in this workspace; 422 for a blank name. |
| `PUT`  | `/api/standard-profiles/{profile_id}` | `{"name"?: "...", "is_default"?: true}` → rename and/or make this the workspace's default profile (unsets the previous default). 404 for an unknown profile; 409 on a name clash. |
| `DELETE` | `/api/standard-profiles/{profile_id}` | Delete a non-default profile; every contract that used it falls back to the workspace default automatically (`ON DELETE SET NULL`) — never a dangling reference. 400 if it is the default profile; 404 if unknown. |
| `GET`  | `/api/standard-profiles/{profile_id}/standards` | That profile's four standards, same shape as `GET /api/standards`. 404 if unknown. |
| `PUT`/`DELETE` | `/api/standard-profiles/{profile_id}/standards/{term_id}` | Save or reset one standard within that specific profile — same validation and shape as the default-profile routes above. |
| `GET`  | `/api/standard-profiles/{profile_id}/clauses` | That profile's expected-clause checklist (MAS-188): the fixed catalog (`liability_cap`, `data_protection`, `insurance`, `indemnification`), each `{id, name, enabled}` — every clause starts enabled. 404 if unknown. |
| `PUT`  | `/api/standard-profiles/{profile_id}/clauses/{clause_id}` | `{"enabled": true\|false}` → enable or disable one clause on this profile; disabled means never checked, never reported "absent" — it simply does not appear. 404 for an unknown profile or clause. |
| `GET`  | `/api/standard-profiles/{profile_id}/policy-rules` | That profile's configured policy content rules (MAS-192): one entry per clause in the catalog, `{id, name, rule_text}` — `rule_text` is `null` where nothing is configured. A rule only ever judges a clause this profile's checklist already found present. 404 if unknown. |
| `PUT`/`DELETE` | `/api/standard-profiles/{profile_id}/policy-rules/{clause_id}` | Set (`{"rule_text": "..."}`, free text) or clear the rule for one clause. Whitespace-only `rule_text` clears it the same as `DELETE`. 404 for an unknown profile or clause. |
| `PUT`  | `/api/contracts/{contract_id}/standard-profile` | `{"profile_id": "<uuid>" or null}` → assign which profile this contract compares against (`null` clears it back to the workspace default); returns the updated `ContractSummary`, with recomputed `deviations`. 422 if `profile_id` belongs to another workspace; 404 if the contract is unknown. |
| `GET`  | `/health` | Liveness: the process answers. Always 200. |
| `GET`  | `/ready` | Readiness: Postgres and Qdrant answer (200) or the failing one is named (503); also reports which chat model is configured. Use this, not `/health`, to know whether requests will succeed. |
